# HullOps API

The backend of [HullOps](../../README.md): a NestJS app that serves a GraphQL API and stores data in PostgreSQL through Prisma 7.

## Setup

From the repository root, start the database first: `docker compose up -d db`. Then, in this directory:

```bash
cp .env.example .env              # DATABASE_URL for the local Postgres container
pnpm exec prisma migrate deploy   # apply migrations
pnpm exec prisma generate         # generate the client into src/generated/prisma
pnpm start:dev                    # http://localhost:4000/graphql
```

Rerun `prisma generate` after cloning and after every schema change. The generated client is gitignored.

### Environment variables

| Variable | Required | Description |
|---|---|---|
| `DATABASE_URL` | yes | Postgres connection string |
| `PORT` | no | HTTP port, defaults to `4000` |
| `NODE_ENV` | no | `production` hides the details of unexpected errors (see [Errors](#errors)) |

## Scripts

| Command | What it does |
|---|---|
| `pnpm start:dev` | Run with hot reload |
| `pnpm build` / `pnpm start:prod` | Compile to `dist/` and run the compiled app |
| `pnpm lint` | oxlint with type-aware rules |
| `pnpm test` | Unit tests |
| `pnpm test -- src/vessels` | Unit tests in one folder (or pass a file) |
| `pnpm test:e2e` | End-to-end tests against the database in `DATABASE_URL` |
| `pnpm exec prisma migrate dev --name <name>` | Create and apply a migration after changing the schema |
| `pnpm exec prisma studio` | Browse the database in the browser |

Always run tests through these scripts. Jest runs in ESM mode and needs the flags they pass.

## Project structure

```
apps/api/
├── prisma/
│   ├── schema.prisma          data model
│   └── migrations/            generated by `prisma migrate dev`; never edit by hand
├── prisma7.config.ts          Prisma config (loads DATABASE_URL from .env)
├── src/
│   ├── main.ts                entry point
│   ├── app.setup.ts           app-wide setup (validation), shared with e2e tests
│   ├── app.module.ts          root module: config, GraphQL, feature modules
│   ├── schema.gql             generated GraphQL schema, committed so API changes show up in review
│   ├── generated/prisma/      generated Prisma client (gitignored)
│   ├── prisma/                PrismaService: the single database client
│   ├── graphql/               GraphQL error formatting
│   └── vessels/               vessels feature
└── test/                      end-to-end tests
```

Each feature follows the same layout:

| File | Role |
|---|---|
| `*.model.ts` | GraphQL output type (`@ObjectType`) |
| `*.input.ts` | GraphQL input type (`@InputType`) with class-validator rules |
| `*.service.ts` | Business logic and database access; the only layer that uses Prisma |
| `*.resolver.ts` | GraphQL queries and mutations; thin, delegates to the service |
| `*.module.ts` | Registers the resolver and service |
| `*.spec.ts` | Unit tests, next to the code they test |

## Data model

Defined in [`prisma/schema.prisma`](prisma/schema.prisma):

- **Order** is the central entity. It belongs to a **Vessel** and to the **User** who created it, and has a service type (`CLEANING` or `PROTECTION`) and a status (`PLANNED` → `IN_PROGRESS` → `DONE`).
- **CleaningDetails** or **ProtectionDetails** hold the service-specific fields, 1:1 with the order. The database doesn't check that they match the order's service type, so the application must.
- **OrderAssignment** links users to the orders they work on.
- **StatusUpdate** is an order's history log, with optional **Photos** stored by object-storage key.
- "Overdue" (`dueDate < now && status != DONE`) is computed when needed, never stored.

## GraphQL API

The schema is code-first: it's generated from the decorated TypeScript classes into [`src/schema.gql`](src/schema.gql) when the app starts. Open http://localhost:4000/graphql to explore it in GraphiQL.

### Vessels

```graphql
mutation {
  createVessel(
    input: { name: "Aurora", imoNumber: "9074729", vesselType: "Yacht", lengthM: 72.5 }
  ) {
    id
    name
  }
}

query {
  vessels { id name imoNumber }
  vessel(id: "…") { name lengthM }   # null if the id doesn't exist
}
```

IMO numbers are validated including their check digit, and must be unique.

### Errors

Every error has a machine-readable `extensions.code`:

| Code | When |
|---|---|
| `BAD_REQUEST` | Input failed validation. The message is "Validation failed", and `extensions.validationErrors` lists each failed rule. |
| `CONFLICT` | The request would create a duplicate, e.g. an IMO number that already exists |
| `NOT_FOUND`, `UNAUTHENTICATED`, `FORBIDDEN` | The matching HTTP exceptions |
| `GRAPHQL_VALIDATION_FAILED` | The query itself is invalid, e.g. it asks for an unknown field |
| `INTERNAL_SERVER_ERROR` | Anything unexpected. With `NODE_ENV=production`, the message is reduced to "Internal server error". |

Example validation error:

```json
{
  "message": "Validation failed",
  "extensions": {
    "code": "BAD_REQUEST",
    "validationErrors": [
      "imoNumber must be a valid 7-digit IMO number",
      "lengthM must be a positive number"
    ]
  }
}
```

The mapping lives in [`src/graphql/format-graphql-error.ts`](src/graphql/format-graphql-error.ts).

## Testing

- **Unit tests** (`src/**/*.spec.ts`) mock Prisma and need no database.
- **End-to-end tests** (`test/*.e2e-spec.ts`) start the whole app and send real GraphQL requests to the database in `DATABASE_URL`. They delete the data they create. CI runs them against a throwaway database.

## Notes on the setup

- **Prisma 7** connects through a driver adapter (`@prisma/adapter-pg`), not a bundled engine. See [`src/prisma/prisma.service.ts`](src/prisma/prisma.service.ts).
- **Generated client location:** the client is generated as CommonJS into `src/generated/prisma`, because `nest build` compiles only `src/`. Import it from there, not from `@prisma/client`.
- **Jest import mapping:** both Jest configs map `./x.js` imports to `./x`, because the generated client imports its own TypeScript files with `.js` extensions.
- **GraphQL version:** `graphql` is pinned to v16 because `@apollo/server` doesn't support v17 yet.
